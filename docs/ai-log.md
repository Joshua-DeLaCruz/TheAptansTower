## 2026-10-28 – M1 step 1: test-scene builder
**Task:** Make an Editor menu item (Tools/Aptans/Build M1 Test Scene) that builds the M1 player test scene from code, so no scene has to be built by hand.
**What the agents did:** The coordinator looked through the empty Unity 6000.4.6f1 project and proposed a six-step M1 plan, which I approved (decisions: thrown dagger with a limited count, input defined in code, I write Health/IDamageable myself, 32 PPU art with visuals on `Visual` child objects). Before the step, "Apthans" was renamed to "Aptans", the log was fixed to LA9 and a starting commit was made. The unity-gameplay agent wrote `Assets/_Project/Scripts/Editor/M1TestSceneBuilder.cs`. It creates a 32x32 placeholder sprite, adds the Ground and Player layers, builds a scene with a pixel-perfect camera, a global 2D light, floor, platforms, walls and a Player (Rigidbody2D + capsule collider), and makes it the only scene in Build Settings. The code-reviewer checked it, and the learning-coach wrote the explanation and this entry.
**Review findings:** No compile problems. Six smaller fixes, all applied: save the new layers to disk right away, re-check the sprite import settings on every run, a null check on the texture importer, two clearer comments, and a warning when the 2D Renderer is not active. Useful catch: the review found that the URP pipeline asset and 2D renderer are missing from Assets/. Looking into that showed an older copy of the project had ended up inside the `.git` folder. I would probably not have spotted this myself until the lighting looked wrong. Still being fixed. The builder has not been tested in Unity yet.

## 2026-10-28 – M1 step 2: player input reader
**Task:** Make one `PlayerInputReader` component that reads all player input (Move, Jump, Dodge, Attack, Throw) with the new Input System and passes it to other scripts through properties and C# events.
**What the agents did:** First the coordinator repaired the git history: local main had no parent and did not connect to GitHub's "Initial check-in", so it was put on top of that commit, the URP settings were restored from it, and with my OK three leftover folders inside `.git` were deleted (an old project copy, a 177 MB Unity cache and a nested old repository). Step 1 was then committed (ed4946f). When I tested step 1, the scene, sprite and layers were missing from this folder, probably because I ran the builder in my backup copy, so I was asked to re-run it here. Lesson: always check which project folder Unity has open before testing. The unity-gameplay agent wrote `Assets/_Project/Scripts/Player/PlayerInputReader.cs` with serialized `InputAction` fields, default keyboard and gamepad bindings in `Reset()` (filled in by `Awake` if empty), polled values (`Move`, `MoveX`, `JumpHeld`), events for one-off presses, subscribe/unsubscribe in OnEnable/OnDisable, Dispose in OnDestroy, a Log Input toggle, and Digital mode for keyboard diagonals. It also made the scene builder add the reader to the Player. The code-reviewer checked it, and the learning-coach wrote the explanation and this entry.
**Review findings:** No must-fixes. Five small fixes, all applied: removed the Play-mode Reset branch, added Dispose in OnDestroy, fixed a comment, documented that JumpReleased does not fire if the reader is disabled while Jump is held (so jump code should poll JumpHeld), and documented that the defaults come back if all bindings of an action are removed in the Inspector. Not yet tested in Unity.
